# M7 Check for Updates… — Plan

**Goal:** Shellforge updates itself from its own GitHub releases, as AiTerm does, and never from
iTerm2's Sparkle feed.

### Task 1: The release feed (ShellforgeCore/Updates)
- Port `ReleaseVersion`, `ReleaseSource` (`Release`, `UpdateError`, `ReleasePage`, `ReleaseDownload`),
  `GitHubReleaseSource`, `ReleaseFeed` and `UpdateCheck`. The image is `Shellforge-<version>.dmg`.
- Ruling: GitHub only. AiTerm's GitLab source and its token handling are left out, with their errors.
- Tests first: AiTerm's `ReleaseVersionTests`, `GitHubReleaseSourceTests` (stubbed transport),
  `ReleaseFeedTests` (the shipped feed is `github:NathanGel/shellforge`) and `UpdateCheckTests`.

### Task 2: Staging and installing
- Port `UpdateStager` and `UpdateInstaller`. Children start through `ChildProcess`, as every other one does.
- The image's one top-level app is staged, whatever its name; its identifier, version and signature decide.
- Tests first: AiTerm's `UpdateStagerTests` (real `hdiutil` and `codesign` on a fake bundle) and
  `UpdateInstallerTests`, all under `TestScratch.root`.

### Task 3: The controller (ShellforgeUI/Updates)
- Port `UpdateController` and `UpdateProgressPanel`; `BuildChannel` reads `ShellforgeDevBuild`.
- A running version that is not `x.y.z` (`unknown`, `3.7.dev`) is a dev build: it is told so and never asks the feed.
- Tests first: AiTerm's `UpdateControllerTests`, through the UI tests' `ScriptedPrompter`.

### Task 4: The app
- `checkForUpdatesFromMenu:` (main menu and status-bar menu) runs Shellforge's controller.
- The app delegate is Sparkle's delegate and refuses every check (`updaterMayCheckForUpdates:`).
- `plists/dev-iTerm2.plist` gains `ShellforgeUpdateFeed` and `ShellforgeDevBuild = $(SHELLFORGE_DEV_BUILD)`.
  Only the Development configuration sets that build setting to `YES`.
- Host test: the feed and dev marker are in the bundle; Sparkle may not check; the menu item reaches Shellforge.

### Task 5: Docs
- A Check for Updates… section in `features.md`, and the changed iTerm2 files in `upstream-hook-points.md`.
