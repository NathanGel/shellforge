# M1b-2 Sidebar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Shellforge's sidebar looks and behaves like AiTerm's — the PROJECTS header, project rows with their provider mark and chevron, task rows with agent marks, branch label and AiTerm's status marks, selection and hover pills, banners and the empty state, dark and 420 pt wide — built only from `ShellforgeDesign`, inside iTerm2's window.

**Architecture:** AiTerm's sidebar views (`~/aiterm/app/Sources/AiTerm/Views/`) are ported into `ShellforgeUI`, changed only where they read AiTerm's model: they read `SidebarModel` and `SidebarTree` instead. The sidebar's hosting view is forced `.darkAqua` (never iTerm2's window), and the Agent hooks sheet is presented in its own dark panel. Features Shellforge does not have yet (Jira, dividers, reviews, terminals, the footer's dials) are left out, not stubbed.

**Tech Stack:** Swift 6 language mode, macOS 13, SwiftUI + AppKit, `ShellforgeDesign`; Swift Testing via `Shellforge/scripts/swift.sh`; the iTerm2 app built with `xcodebuild` for the live check.

**Spec:** Shellforge PRD (Claude Doc 89fd80a8-5fcf-4423-a8d6-c62f8512a481) W1–W3, W8; the user: "visually and functionally it should be exactly what AiTerm is, but inside an iTerm fork." `Shellforge/Sources/ShellforgeDesign/README.md` (AiTerm's design spec) governs every view.

## Global Constraints

- Source: AiTerm (`~/aiterm`, GPLv3, Laurens D'Hondt). Ported files start `// Ported from AiTerm (app/Sources/AiTerm/Views/<file>.swift), GPLv3, Laurens D'Hondt.` Nothing in `~/aiterm` changes.
- Every colour, size, radius, spacing and type style comes from `ShellforgeDesign` (`DesignRulesTests` scans `ShellforgeUI`). At the end of this plan `DesignRulesTests` lists no exception for `ShellforgeUI` except ported AiTerm ones (the stale check proves the placeholder ones are gone).
- Dark only, inside iTerm2: the sidebar's `NSHostingView.appearance` is `.darkAqua`, and every window, panel or sheet it opens sets its own; never `.preferredColorScheme` (it would darken iTerm2's window), never `NSApp.appearance`.
- macOS 13: no `@Observable`/`@Bindable`, `.onKeyPress`, two-argument `onChange`, `selectionDisabled`, `allowsWindowActivationEvents`, `Group(subviews:)`. A ported line that uses one is changed and ledgered.
- Width: `Size.sidebarWidth` (420); the iTerm2 window's layout already takes the sidebar's width from `iTermShellforgeSidebar.width`.
- Out of scope (they arrive with their features): Jira badges, dividers and groups, reviews/MR rows, terminals, the footer (CONTEXT/USAGE, M1c-3c), keyboard focus model, interface-size preference UI, toasts.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Nothing is pushed without asking.

## Review Focus

1. **A light iTerm2** (System Settings › Appearance: Light): the sidebar, its menus and the Agent hooks sheet stay dark; iTerm2's terminal window does not turn dark. (Task 1: `theSidebarDrawsDarkInALightWindow`; Task 5: `theHooksPanelIsDark`.)
2. **A long task title or branch name** in a 420 pt column: titles wrap or truncate as AiTerm's do (title one line, branch middle-truncated), and the status mark never moves off the trailing edge. (Task 3: `aLongBranchIsMiddleTruncatedAndTheMarkStays`.)
3. **A task with tabs running different agents, or more than two** — AiTerm's avatar group shows at most two marks and a `+n`. (Task 3: `avatarsShowTwoAndCountTheRest`.)
4. **No projects yet** — AiTerm's empty state with its Add Project button, not a blank column. (Task 4: `anEmptyWorkspaceShowsTheEmptyState`.)
5. **Clicking a row that is already selected, or hovering then selecting** — one pill, the selection's, never a hover wash on top. (Task 2: ported `SidebarRowGeometryTests` — selection and hover paint the same pill.)

import AppKit

@testable import ShellforgeCore

@MainActor @Suite struct SidebarViewTests {
    private let folder = FileManager.default.temporaryDirectory.appendingPathComponent("sf-view-\(UUID().uuidString)")

    /// The sidebar drawn and settled, and every accessibility label in it, in order.
    private func labels(_ model: SidebarModel) -> [String] {
        let host = ShellforgeSidebar.makeView(model: model, chooseFolder: { nil },
            hooks: AgentHooksModel(integrations: HookIntegrations(home: folder, resources: .bundled(resourceURL: nil)), names: [:]))
        host.frame = NSRect(x: 0, y: 0, width: ShellforgeSidebar.width, height: 600)
        let window = NSWindow(contentRect: host.frame, styleMask: [.titled], backing: .buffered, defer: false)
        window.contentView = host
        RunLoop.main.run(until: Date().addingTimeInterval(0.1)); host.layoutSubtreeIfNeeded()
        func walk(_ element: Any) -> [String] {
            let label = ((element as? NSAccessibilityElementProtocol) as? NSObject)?.value(forKey: "accessibilityLabel") as? String
            let children = (element as? NSObject)?.value(forKey: "accessibilityChildren") as? [Any] ?? []
            return (label.map { [$0] } ?? []) + children.flatMap(walk)
        }
        return walk(host)
    }

    @Test func anEmptyWorkspaceShowsTheEmptyState() throws {
