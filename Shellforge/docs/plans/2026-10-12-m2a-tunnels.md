# M2a SSH Tunnels Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A project lists its SSH tunnels (`Host` aliases from `~/.ssh/config` that have `LocalForward` lines). Each can be started and stopped from the sidebar, with live state: stopped, connecting, up, or failed with `ssh`'s last error line. The daemon supervises each tunnel and restarts it with backoff after a drop. Tunnels auto-start by rule: never, on app launch, or when a task of the project opens. A task's tabs get each running tunnel's port as `SHELLFORGE_TUNNEL_<NAME>_PORT`. Quitting stops them.

**Architecture:**
- **ShellforgeCore:**
  - `SSHConfig` reads `~/.ssh/config`, read-only: `Host` aliases, their `LocalForward` lines and `Include`d files.
  - `Project` gains `tunnels: [TunnelDefinition]`, holding the alias and the auto-start rule.
  - The daemon protocol gains `tunnels.start`, `tunnels.stop` and `tunnels.list`, and a `tunnel.changed` event.
- **Daemon (Python):** a `TunnelSupervisor` runs `ssh -N` per started alias and keeps each one's state. The app hands it the login environment, so `ssh` finds the user's `PATH` and agent socket. It broadcasts each change, restarts dropped tunnels with backoff, and stops them all when the daemon stops.
- **ShellforgeUI:**
  - `DaemonLink` keeps the tunnels' states, and `SidebarModel` starts and stops tunnels and auto-starts them.
  - A Tunnels sheet edits a project's tunnels.
  - The project section draws a row per tunnel.
  - New tabs get the port variables.

**Tech Stack:** Swift 6 language mode, macOS 13, SwiftUI; Swift Testing via `Shellforge/scripts/swift.sh`; Python 3 asyncio daemon with pytest (`(cd Shellforge/daemon && .venv/bin/pytest -q)`).

**Spec:** Shellforge PRD (Claude Doc 89fd80a8-5fcf-4423-a8d6-c62f8512a481), "Requirements: SSH tunnels".
- **Model:** "a `Host` alias from `~/.ssh/config`, run as `ssh -N <alias>` … The app does not copy the forwards; it reads them to show the ports and check them. Per tunnel the app stores only: the alias, the project it belongs to, and an auto-start rule (never, on app launch, or when a task of the project opens)."
- **The requirements table.** Command-palette start/stop, bytes and uptime, interactive input, and "keep running" are M2b. The per-project SSH split pane from New Task is M2b too.

## Global Constraints

- **`~/.ssh/config` is only read**, never written. Tunnel settings live in Shellforge's workspace (`~/Library/Application Support/Shellforge/workspace.json`).
- **Nothing starts until the user starts a tunnel once or sets its auto-start rule** (PRD: "Nothing changes on the machine without an explicit click").
- **`ssh` invocation:** `ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -o ServerAliveCountMax=3 -o BatchMode=yes <alias>`.
  - `BatchMode=yes`: a host-key or 2FA prompt fails the tunnel with ssh's line rather than hanging. Answering prompts in a tab is M2b.
  - The environment comes from the app (`LoginEnvironment` resolved, as `CommandLauncher` uses).
- **No other process** is started for tunnels: the daemon's `asyncio.create_subprocess_exec` for `ssh` only, in `tunnels.py`. Swift starts nothing new.
- **Tests:**
  - No test reads the real `~/.ssh/config` or reaches the network.
  - Daemon tests run a fake `ssh`: a script on a temporary `PATH` that sleeps, exits at once with a message, or exits after a delay.
  - Swift tests parse config text from temporary files.
- **Protocol:** stays `VERSION = 1`, since only new methods and an event are added, and old clients ignore an unknown event. Wire fixtures are regenerated (`SHELLFORGE_UPDATE_WIRE_FIXTURES=1`), and the Swift `WireContractTests` follow.
- **macOS 13:** no `@Observable`, no `Mutex`. Design tokens only (`DesignRulesTests`).
- **Commits** end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; stage by path; never push.

## Review Focus

1. **A tunnel whose local port is already taken** (another tunnel, or a plain `ssh <alias>` in a tab).
   - It fails with ssh's own line ("bind … Address already in use") and is not restarted in a loop: a failure within the first seconds is not a drop.
   - Test: Task 2 `aTunnelThatFailsAtOnceIsFailedNotRestarted`.
2. **A tunnel that drops after being up** (network gone).
   - It goes connecting and restarts with backoff (1, 2, 4… capped at 30 s), and is up again when ssh stays.
   - Stop during backoff stops it for good.
   - Tests: Task 2 `aDroppedTunnelRestartsWithBackoff`, `stopDuringBackoffStopsForGood`.
3. **The daemon stopping** (app quit).
   - Every ssh it started is terminated, with no orphan left holding the ports.
   - Test: Task 2 `stoppingTheDaemonEndsEveryTunnel`.
4. **`~/.ssh/config` with `Include`, wildcards, `Match` blocks, comments, quoted values, `LocalForward` in each of its forms** (`port host:port`, `bind:port host:port`, `[v6]:port`).
   - Only concrete aliases with forwards are offered, with their ports.
   - Wildcard hosts and `Match` blocks are skipped.
   - Tests: Task 1 `SSHConfigTests`.
5. **A project's tunnel whose alias is gone from the config, or a workspace from before tunnels.**
   - The row says "Not in ~/.ssh/config" and cannot start. Old workspaces load with no tunnels.
   - Tests: Task 1 `aProjectFromBeforeTunnelsHasNone`; Task 4 `aTunnelMissingFromTheConfigCannotStart`.

### Task 2: The daemon's tunnel supervisor

**Files:**
- Create: `Shellforge/daemon/shellforged/tunnels.py`, `TunnelSupervisor`:
  - `__init__(broadcast, clock=time.monotonic, ssh="ssh", up_after=2.0, backoff_cap=30.0)`.
  - `async start(alias, environment)`: starts, or does nothing when the tunnel is connecting or up.
  - `async stop(alias)`, `list() -> list[dict]`, `async stop_all()`.
  - States: `stopped`, `connecting`, `up`, `failed`, each with `error` (ssh's last stderr line) and `since`.
  - A tunnel is `up` once its `ssh` has run `up_after` seconds.
  - An exit before that is `failed`, with the stderr line, and is not restarted.
  - An exit after being up is a drop: the tunnel is `connecting` again, with a restart after backoff (1, 2, 4… ≤ `backoff_cap`), and the backoff resets after a run that lasted 60 s.
  - `stop` cancels a pending restart, terminates `ssh` (SIGTERM, then SIGKILL after 2 s), and sets `stopped`.
  - Each state change broadcasts `tunnel.changed` with `{alias, state, error, since}`.
- Modify: `protocol.py`:
  - add `TUNNEL_CHANGED = "tunnel.changed"` to `EVENTS`;
  - `service.py` registers `tunnels.start` (`{alias: str, environment: {str: str}}`), `tunnels.stop` (`{alias}`) and `tunnels.list`;
  - `Service.stop()` awaits `tunnels.stop_all()` first;
  - `workspace.snapshot` gains `tunnels`;
  - `Service.__init__` takes `tunnels: TunnelSupervisor | None`, built by default over `rpc.broadcast`.
- Modify: `tests/conftest.py` `make_service` can pass `tunnels=`.
- Test: `Shellforge/daemon/tests/test_tunnels.py`. A fake `ssh` written to `tmp_path/bin/ssh`, with the environment's `PATH` pointing there. It reads `FAKE_SSH_MODE` from the handed environment: `stay`, `fail` (prints "bind [127.0.0.1]:5432: Address already in use" to stderr, exits 255), or `drop-after:<s>`. `up_after` is 0.2 in tests and backoff starts at 0.1, so tests run fast. Cases:
  - `aTunnelComesUpAndIsBroadcast`;
  - `aTunnelThatFailsAtOnceIsFailedNotRestarted` (error is ssh's line);
  - `aDroppedTunnelRestartsWithBackoff`;
  - `stopDuringBackoffStopsForGood`;
  - `startingARunningTunnelDoesNothing`;
  - `stoppingTheDaemonEndsEveryTunnel` (the fake's pid is gone);
  - `theSshArgumentsAreTheTunnelsOwn` (the fake writes its argv to a file);
  - `theEnvironmentIsTheOneHandedIn`;
  - an RPC round trip through `stack`: `tunnels.start`, then the `tunnel.changed` event, then `tunnels.list`;
  - bad params, in `test_malformed_params_are_bad_params_not_internal_errors`.
- Regenerate the wire fixtures.
