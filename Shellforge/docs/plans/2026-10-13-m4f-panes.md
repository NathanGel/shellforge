# M4f Panes: ⌘D starts no agent, Close Pane, panes join their task — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The user's three findings of 13 October 2026:
- ⌘D in a task's tab typed the agent and its prompt again in the new pane.
- Close Tab on a task split with ⌘D asked to remove the task.
- A pane split off a task's should belong to the task.

**Spec:** the user: "cmd + d … if claude was running with a prompt it'll open a new one with that prompt, that is not desired". Close Tab should "only ask to remove if it was the only tab linked to a certain task"; their extra "tab" was a ⌘D pane.

## Global Constraints

- iTerm2's own behaviour stays: ⌘D and ⌘T split or open with the current profile, in the current folder.
- Only the agent's one-shot initial text is dropped.
- Closing goes through iTerm2's confirmation (`closeSessionWithConfirmation:` for a pane, `closeTabIfConfirmed:` for a tab).
- A window is never emptied: M4e's `TaskTabs.closeOne`.
- macOS 13; commits by path, ending `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; never push.

## Review Focus

1. **⌘D before the initial text was sent** (a slow shell). Expected: the agent's tab still gets it once; the split never does.
2. **Closing the agent's pane of a split task tab.** Expected: the other pane stays, still the task's (it carries the tag).
3. **A split Other tab.** Expected: Close Pane closes the focused pane only.

### Task 1: The agent's initial text is sent once
- `PTYSession.sendInitialText`: a profile carrying `Shellforge Initial Text Once` clears its session's `KEY_INITIAL_TEXT` once the text is read.
- Splits (⌘D) and new tabs (⌘T) copy the session's profile without it.
- `taskTabProfile` sets the flag whenever it sets initial text.
- Test: `ShellforgeHostTest.testATaskTabsInitialTextIsOneShot` (the profile carries the flag).
- Live check: ⌘D in a task's tab starts a plain shell.

### Task 2: Panes join their task, and Close Pane
- `TabSnapshot.paneCount`.
- The host tags an untagged pane in a tab holding a task's (or terminal's) pane with that task, on each refresh.
- `TerminalHost.closePane(ofTab:)` closes the tab's focused pane with iTerm2's confirmation.
- `paneCount(ofTask:)` replaces `tabCount`: tagged panes in every window.
- `SidebarModel.closeTab(_:)`:
  - a split tab closes its focused pane (Close Pane);
  - an unsplit tab is the task's last only when the task has one pane, and only then asks Remove;
  - else the tab closes.
- The menu item reads "Close Pane" on a split tab, "Close Tab" otherwise; the task row follows its current tab.
- Tests (`CloseTabTests`):
  - `aSplitTaskTabClosesItsFocusedPane`
  - `aTaskWithTwoPanesClosesAPaneWithoutAsking`
  - `aTasksLastPaneAsks`
  - `aSplitOtherTabClosesAPane`
  - `theMenuSaysPaneOnASplitTab`
- Generic tagging rule in `TaskTabs.untaggedPanes(...)`, test `panesSplitOffATaskJoinIt`.
